# CityPulse UI Rules

The UI serves ordinary residents first. It must not look like an admin dashboard, crypto dashboard, enterprise analytics platform, or complicated AI console.

## Main Page Order

```text
Header
City Status
Current Situation
What's Happening
Live Map
Recent Updates
Why It Matters
Why These May Be Linked
Data Sources
```

Do not rearrange without good reason.

## Header

Only show CityPulse, Jaipur, `LIVE | REPLAY`, and `Updated X ago`. Keep controls minimal.

## Current Situation

Show exactly four cards: Weather, Air Quality, Transport, and Local Reports.

## Status Names and Colors

```text
Stable    → Green
Watch     → Yellow
Elevated  → Orange
High      → Red
```

Use semantic colors consistently without making the page aggressively colorful.

## Simple Language

Prefer `What's Happening`, `Why It Matters`, `Why These May Be Linked`, `Data Sources`, and `Recent Updates`. Avoid `Analytics Engine`, `Intelligence Center`, `Fusion System`, `Correlation Matrix`, and `Predictive Intelligence`.

## Buttons

Keep buttons to a minimum. Approved primary controls are `LIVE | REPLAY`, Play, Pause, the timeline slider, and map interaction. Do not add decorative CTAs.

## Causation Wording

Always say `Possible Link`, never `Cause`, `Confirmed Link`, or `AI Proven`.

## Data Labels

Always label `Transport — Simulated` and `Local Reports — Simulated`.
